# Does Model API support Zero Data Retention (ZDR)?
Yes. Zero Data Retention (ZDR) is available for qualified Meta Model API teams. When ZDR is enabled, your prompts and the model's responses are processed in real time and aren't stored by Meta after the response is returned, except where retention is required to comply with the law or to address misuse.
ZDR isn't part of standard usage and can't be turned on from the web UI. Meta enables it for a team after reviewing the request. To request ZDR, fill out the contact sales form so the sales team can confirm your team's eligibility and enable it for you.
## How do I know if ZDR is enabled for my team?
When ZDR is enabled, the **Data** section of your team's Settings page shows **Zero Data Retention** as **Enabled**.
## Which models support ZDR?
ZDR currently covers these models on Meta Model API:
* Muse Spark 1.3, Muse Spark 1.2 and Muse Spark 1.1 (`muse-spark-1.3`, `muse-spark-1.2`, `muse-spark-1.1`)
* Muse Wonder (`muse-wonder-1.0`)
* Muse Ember (`muse-ember-1.0`)
* Muse Image (`muse-image-1.0`)
ZDR doesn't cover the Contributor-mode variants of these models. For what each model does, see Models.
## When does ZDR apply?
ZDR applies to Model API requests made with an API key that belongs to a ZDR-enabled team. Requests made with a personal account, or with a key from a different team, aren't covered.
ZDR applies only to calls made directly to Meta Model API. Calls routed through third-party platforms follow that platform's data retention policy.
If you use Muse Code, ZDR applies to the model requests it sends with an API key from your ZDR team. Muse Code uses the `META_API_KEY` environment variable ahead of a stored key or a browser sign-in, which may belong to a different account, so set `META_API_KEY` to your ZDR team's key. Muse Code can also send data to Meta separately from its model requests, through web search, telemetry and feedback reports. To turn these off, see Control what Muse Code sends to Meta.
## What can I use with ZDR?
With ZDR enabled, you can use:
* **Text generation**: Chat Completions, Responses and Messages requests, as long as they're stateless. On Responses, leave `store` unset or set it to `false`.
* **Multi-turn reasoning**: On Responses, carry reasoning between turns by replaying encrypted reasoning content instead of referencing a stored response. See Multi-turn reasoning.
* **Web search**: Search queries and results are processed in real time and aren't stored.
* **Image generation and editing**: Keep the default `b64_json` response format, so generated images come back in the response instead of as a signed URL. To edit an image, send it as a base64 data URL or a public URL in a JSON request. Multipart uploads aren't supported, and the OpenAI SDK's image edit method uses them. To edit an image over several turns, pass the previous image back in. See Manage state yourself.
## Which features aren't available with ZDR?
Because your content isn't stored under ZDR, features that rely on storing your prompts, attachments, or responses are turned off, and requests that use them are rejected. With ZDR enabled, the following aren't available:
* Stateful requests that store a response or reference one server-side, such as `store: true`, `previous_response_id` and stored reasoning items
* Background (asynchronous) requests
* File uploads, including multipart image uploads
* Contributor mode, including Contributor-mode variants on Meta Model API and the Contributor mode setting in Muse Code
* Playground chat history (conversations created before ZDR was enabled stay visible until deleted)
Other features that require storing prompts or responses may also be unavailable.
## What data does Meta still retain under ZDR?
Even with ZDR, Meta retains a few limited categories of data:
* **Policy violations**: If a request is flagged for an Acceptable Use Policy violation, Meta may retain the associated inputs and outputs for up to 2 years for abuse detection, integrity and content-safety enforcement, and to meet legal obligations.
* **Usage statistics**: Token, request, and tool-call counts are retained and shown in your usage dashboard, without the prompts and responses themselves.
* **Account and team data**: Administrative details such as account emails and team information are retained.
* **Operational metadata**: Details such as model name, latency, and app ID are retained for billing, analytics, and operations.
* **Support feedback**: Anything you send through the support or contact form is retained for support and investigation.
* **Third-party integrations**: Calling function tools or remote MCP servers doesn't turn off ZDR, but ZDR covers only Meta's handling of your content. Data sent to a third-party service follows that service's own terms and data handling practices. Review them separately.
For how Meta handles data outside ZDR, see How does Meta handle my data? and the AI Developer Legal Center.
