Enterprise features

Restrict inference for your Enterprise account to a selected region

Data residency restricts inference on your account to a single region. Once a region is set, every request must use that region’s API endpoint and a model served in that region.It does not change how your requests are routed. Turning it on will not move existing traffic into the region. This setting _enforces_ all requests to be in the set region, and rejects the ones that are not.

Residency applies **account-wide**: every API key on the account is restricted to the selected region.

## Available regional restrictions

| Regional restrictions | API endpoint | Serverless | Dedicated deployments |
| --- | --- | --- | --- |
| None | `api.fireworks.ai` | Any model | Any region |
| US | `us.api.fireworks.ai` | [US-only Serverless](https://docs.fireworks.ai/serverless/us-only-serverless) | [`US` multi-region](https://docs.fireworks.ai/deployments/regions), or a single US region such as `US_IOWA_1` |

**None** is the default. For a region that is not listed, contact [sales](https://fireworks.ai/company/contact-us).

## Before you switch it on

A residency change takes effect as soon as you save it, and anything that does not match the region is rejected.

### Serverless

Point your clients at the region’s API endpoint and change every request to use a model from that region. See [US-only Serverless](https://docs.fireworks.ai/serverless/us-only-serverless) for the US endpoint and model IDs.

### Dedicated deployments

Every dedicated deployment must run in the selected region. Create it with `--region` set to that region, or to a single region inside it. See [Regions](https://docs.fireworks.ai/deployments/regions).Check what you already have before you save the setting:

*   **New deployments outside the region are rejected** when you create them.
*   **Existing deployments are not checked, moved, or stopped** when you switch the setting on. One outside the region keeps running and keeps costing you money, but requests to it are rejected. Replace it first.
*   **You can move a deployment to another region inside your residency region, but not out of it.**

## Configure in the console

Account admins can set data residency in the Fireworks console at **Settings → Governances → Data Residency** ([open in console](https://app.fireworks.ai/settings/governances/region-access)).Select the region and save. The console asks you to confirm that your clients already use the endpoint and models shown for that region.

## Pricing

Regional models are priced at a premium over the base serverless price for the same model. See [Serverless pricing](https://docs.fireworks.ai/serverless/pricing).

## Limitations

The following are not supported while a region is set: calls are rejected, and stay rejected until you clear the setting.

*   **Training.** Fine-tuning and training jobs are blocked. Support is coming soon.
*   **Model routers.** A `firerouter/...` id can pass a request through to a third-party provider, which Fireworks cannot constrain to a region. See [APIs and SDKs](https://docs.fireworks.ai/ecosystem/firerouter/apis-and-sdks).
*   **BYOC.**[BYOC](https://docs.fireworks.ai/ecosystem/integrations/byoc/overview) deployments run in your own cloud account, so Fireworks cannot enforce where they run.
